# Moto G4: untrusted CAPTCHA certificate

Observed screenshot: React Native WebView reports `SSL error: The certificate authority is not trusted`, code 3. The page has not loaded; this is not a rejected vote, an invalid CAPTCHA binding or a site-key mismatch. On the reported Moto G4: Android 7.0, security patch 1 April 2018, Chrome 119.0.6045.193. The newer phone working points to a device/network trust difference, but the exact failed hostname and certificate chain still need inspection.

1. Enable automatic date, time and timezone under Android Settings → Date & time; confirm the year/date are correct. A wrong clock can also break TLS, although this screenshot specifically names CA trust.
2. In Play Store check updates for both Google Chrome and Android System WebView. Under Settings → Apps note the active WebView provider/version; on Android 7 Chrome can supply WebView, so the two versions are not necessarily interchangeable. Developer options → WebView implementation (if available) shows the selected provider. Restart the phone after updating.
3. Open the exact configured `EXPO_PUBLIC_TURNSTILE_CHALLENGE_URL` hostname in Chrome on that Moto G4. Compare the same URL on the newer phone, on the same network. If the outer page loads but embedded verification fails, inspect `challenges.cloudflare.com` too. Do not bypass certificate warnings. A challenge page without its vote binding may correctly show “invalid challenge”; this browser check is for TLS/page loading only, not vote completion.
4. Repeat on mobile data/another trusted Wi-Fi. Check for captive portals, VPNs, corporate/school filtering or antivirus TLS interception. A network can replace a certificate with a CA trusted by one phone but not another.
5. If the old phone still fails, capture the failing hostname, selected WebView version, certificate issuer/validity and complete served chain from browser debugging. Check that hostname's certificate chain with a public TLS diagnostic. The Worker hostname and Cloudflare verification iframe are separate TLS connections. Do not assume a particular missing root solely from the screenshot.
6. Android 7 no longer receives current Chrome support; Chrome 119 is the last Chrome release supporting Android 7. Updating the app does not refresh the OS trust store, and updating WebView cannot guarantee a missing system root is added. If there is no maintained OS upgrade available, use a supported newer device/OS for the verification test. A site operator may evaluate a correctly configured full certificate chain/custom verification hostname compatible with target trust stores, but this must retain HTTPS and be tested; it cannot repair an unsupported browser engine or Cloudflare's own chain.

Official references: Chrome system requirements https://support.google.com/chrome/a/answer/7100626 and Turnstile supported browsers https://developers.cloudflare.com/turnstile/reference/supported-browsers/ . Installation compatibility does not guarantee a discontinued browser engine remains supported by the CAPTCHA provider.

This change keeps TLS verification enabled, replaces the raw blank native error page with a helpful certificate-specific message, and checks exact navigation origins. It does not install CA certificates, accept invalid TLS or claim the old phone is fixed without a device retest. No private key, CAPTCHA token or voting credential is needed for these diagnostics.
