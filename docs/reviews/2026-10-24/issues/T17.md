# [Security] Independent account/device duplicate guards and protected physical-device actions

Keep device/question and account/question uniqueness, session generation, idempotency and request-bound server verification. Guest daily votes use the device guard; signed-in votes use both. A login-day delay is not a substitute and cannot deduplicate repeated requests from an already eligible session. Retain honest one-device/account limits without claiming one unique human. No universal stable device ID or perfect reinstall resistance is promised.

Extend protected gateway/attestation/risk handling to Brewing upvotes and deprecate the unprotected direct authenticated write path. New guest votes must not inherit the last account's ownership. Recommend tablet support; store filters/sideload restrictions are not integrity proof, and attestation is not a universal phone-vs-tablet classifier. Private account/device-session mapping is many-to-many, minimal and retention-bounded. For upvotes, propose an additional device/day cap (shared-device exclusion requires owner approval). See points 2,7,10,13–15,26 and the offline counterexamples.
