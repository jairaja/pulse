Extend/update the owner's existing social-sharing issue instead of creating a duplicate. All published Brewing/live/Past Results questions and a newly published submission have native share/Copy link actions, including guests. Use a stable public occurrence ID that resolves submission → live daily question → exact finalized result, handles removed/private states, and preserves destination through sign-in without automatically voting. Configure owned HTTPS domain, iOS Universal Links and Android App Links. Without the app, show public preview plus appropriate store/Open app controls; embedded-browser and user preference behavior needs fallback. Normal store installation does not guarantee deferred routing; MVP asks user to tap the original link after installing. Test real share targets separately; do not build on retired Firebase Dynamic Links or invasive attribution. See point 1.
