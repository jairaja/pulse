# [Technical] Benchmark vote storage/read models before partitioning at projected scale

Keep one logical indexed votes table and finalized question_results snapshots rather than one independently managed table per question. Benchmark real read/write mixes, midnight contention, history, index/row sizes, retention/WAL/backups and pool limits before declarative time/hash partitioning. Preserve global account/device/idempotency uniqueness and question-date FKs across partitions.

Model 1K/100K/1M/100M daily active voters with explicit participation/burst/storage assumptions; no price or single-instance capacity guarantee. Table statistics are not exact authoritative vote totals. Limit public polling/counter hot rows and use bounded cached read models. Source arithmetic: docs/requirements/capacity-and-storage.md; model is not a hosted load test. See point 25.
