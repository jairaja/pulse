# [Technical] One-time consent-based device history import at verified account creation

Replace automatic every-session history claims with a server-enforced first-verified-signup entitlement, bound to the originating device/session and frozen eligible history. Recommend opt-in; make no pre-OTP account-enumerating email lookup. Existing accounts on any later device restore canonical account history only. Applied requests retry idempotently; declined consent stays declined. Import only server-accepted unowned votes, never arbitrary local records or another account's answers. No changes to existing vote totals/choices.

P0 current gap: lib/auth.tsx attempts claimAccountHistory whenever an account session appears; a checkbox alone cannot implement this rule. Separate device security associations from history ownership so new guest votes after logout are not attributed to the last signed-in account. Test same/different-device signup races, shared devices, response loss, decline then re-login, account deletion/recovery and privacy-safe used-device receipts. See points 4–5 and 26.
