# Language/preferences and community selection rollout

This branch changes app JavaScript and adds two forward migrations. It does not deploy hosted changes, build a new APK, implement single-device session enforcement, or enable announcement/admin services.

1. Merge the reviewed branch, pull main locally, run `npm ci` with the project's pinned Node/npm toolchain.
2. Confirm the checkout is linked to the intended hosted development Supabase project. Run `npx supabase db push --dry-run`. Review pending migrations, especially `202610200004_account_preferences.sql` and `202610200005_community_selection.sql`. Then run `npx supabase db push`. Preserve existing migration history and data; do not reset hosted tables.
3. Migration 005 can catch up **today's** missing live question from the eligible open queue immediately. Inspect the community queue first: accumulated upvotes choose a winner, even if all eligible candidates have zero votes (then newest wins). Schedule/reserve today's date explicitly if an administrator's question must take priority. Old unselected questions remain open; hidden/selected ones are excluded. This is a behavior change from manual-only selection.
4. Verify `cron.job` has the single active `pulse-daily-finalization` midnight schedule (`0 0 * * *`) and cron timezone is UTC/GMT. No noon task is needed. Today/Past Results reads repair a missed rollover without opening a future date or inventing votes for missed days.
5. Run `npm run typecheck`, `npm run verify:typecheck-scope`, `npm run lint`, `npm run test:security`, and `npm run verify:database`. Local database tests live in `supabase/tests/database`. They contain test-only fixtures and must run in disposable test databases, not pasted into hosted SQL Editor.
6. Rebuild Android preview: `npx eas-cli@latest build --platform android --profile preview`. Install the new APK. Expo Go/development clients may reload updated Metro JS (`npx expo start --clear`) if the native dependencies already match. No new package, secret or Edge Function deployment is needed for this change.
7. On a guest install, choose each language in Settings and restart. Arabic/Urdu should mirror layout; native language names remain readable. Guest choice is local and will not follow a new device or storage clear. Theme still follows system when selected.
8. Sign in as A, set language/theme, sign in as A on a second device: saved settings must load, rather than being overwritten by that device's defaults. Make an offline change, restart, reconnect and confirm it syncs. Switch A/B and check preferences remain independent. The requested one-active-device rule is specified only; existing sessions are not forcibly revoked by this branch.
9. Verify selected stored question translations display in Today, preview and results. If absent, original content remains visible. This does not invoke AI translation or pretend an untranslated community question has a detected source language (`und` until the content pipeline exists). Human review of all catalog text, RTL/large-font rendering and platform accessibility remains necessary before production rollout.
10. With two accounts, confirm guest upvotes are unavailable, own upvote disabled, server self-upvote denied, and one total upvote per account/UTC day. Keep old open candidates across multiple days and test totals/ties at midnight; an administrator's already scheduled date wins. Keep the app on Past Results/Brewing at the boundary to verify automatic refresh without first opening Today. Network/suspended apps update after foreground/reconnect; a connected active app still needs request latency.

When Apple signing is ready, repeat steps 7–10 in the signed physical-device iOS build. iOS Simulator can cover layouts/auth/preferences, but cannot validate physical-device voting eligibility.
